Pickup Service API

REST API untuk menjadwalkan penjemputan paket, mengecek tarif ongkir, dan melacak status pengiriman barang dari gudang atau toko Anda sampai ke tangan penerima.

Base URL https://api.pickup.local/v1 Format JSON Auth Bearer Token (JWT)
01

Dapatkan token

Login dengan API key untuk menerima access token.

02

Cek area & tarif

Pastikan alamat terjangkau dan hitung ongkos kirim.

03

Buat pickup

Jadwalkan kurir menjemput paket di alamat pengirim.

04

Lacak resi

Pantau status lewat endpoint tracking atau webhook.

Format respons

Semua respons menggunakan amplop yang sama. Field success menandakan hasil, data berisi payload, dan message berisi pesan yang bisa dibaca manusia.

Contoh respons
{
  "success": true,
  "message": "Pickup berhasil dibuat",
  "data": { ... },
  "meta": { "request_id": "req_8f2a91c0" }
}

Autentikasi

Setiap request (kecuali POST /auth/token) wajib menyertakan header Authorization berisi access token. Token berlaku selama 1 jam; minta token baru jika menerima error 401.

Header
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json
Accept: application/json
Simpan api_key dan api_secret di server (mis. file .env). Jangan pernah menaruhnya di kode frontend atau repository publik.

Siklus Status Pickup

Setiap pickup bergerak melalui status berikut. Pickup hanya bisa dibatalkan atau dijadwal ulang selama statusnya masih pending atau assigned.

pending→ assigned→ on_the_way→ picked_up→ in_transit→ delivered
cancelledfailed
StatusKeterangan
pendingPickup dibuat, menunggu kurir ditugaskan.
assignedKurir sudah ditugaskan ke pickup ini.
on_the_wayKurir sedang menuju alamat pengirim.
picked_upPaket sudah diambil kurir, nomor resi (AWB) aktif.
in_transitPaket dalam perjalanan / transit di hub.
deliveredPaket diterima oleh penerima.
cancelledDibatalkan oleh pengirim.
failedPenjemputan gagal (alamat tidak ditemukan, pengirim tidak di tempat, dll).

Kode Error

API memakai kode status HTTP standar. Saat gagal, success bernilai false dan field errors berisi detail per-field.

HTTPArti
200 OKRequest berhasil.
201 CreatedData baru berhasil dibuat.
400 Bad RequestFormat request salah.
401 UnauthorizedToken tidak ada, salah, atau kedaluwarsa.
403 ForbiddenToken valid tapi tidak punya akses ke resource.
404 Not FoundData tidak ditemukan.
409 ConflictAksi tidak sesuai status (mis. batalkan pickup yang sudah diambil).
422 UnprocessableValidasi field gagal.
429 Too Many RequestsMelebihi rate limit.
500 Server ErrorKesalahan di sisi server.
Contoh error422
{
  "success": false,
  "message": "Validasi gagal",
  "errors": {
    "sender.phone": ["Nomor telepon wajib diisi"],
    "package.weight": ["Berat minimal 0.1 kg"]
  }
}

Webhook

Daftarkan URL callback di dashboard agar server Anda menerima notifikasi setiap kali status pickup berubah, tanpa perlu polling. Request dikirim dengan method POST dan header X-Pickup-Signature (HMAC-SHA256 dari body memakai api_secret).

EventDipicu ketika
pickup.createdPickup baru berhasil dibuat.
pickup.assignedKurir ditugaskan.
pickup.picked_upPaket sudah diambil kurir.
shipment.deliveredPaket diterima penerima.
pickup.failedPenjemputan gagal.

Balas dengan HTTP 200 dalam 10 detik. Jika gagal, webhook dikirim ulang maksimal 5 kali dengan jeda bertahap.

Payload webhook
{
  "event": "pickup.picked_up",
  "timestamp": "2026-11-24T10:42:13+07:00",
  "data": {
    "pickup_id": "PCK-20261124-0007",
    "awb": "PS2611240007ID",
    "status": "picked_up",
    "courier": { "name": "Budi Santoso", "phone": "081234567890" }
  }
}

Rate Limit

Setiap API key dibatasi 60 request per menit. Sisa kuota dikirim lewat header respons berikut:

Response headers
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 57
X-RateLimit-Reset: 1764045780
